# Проєкт REST API: Система бронювання аудиторій

## 1. Ресурси та зв’язки
В API виділено наступні основні ресурси:

1. **`rooms`** (Аудиторії)
   * Атрибути: `id` (readOnly, призначає сервер), `name` (рядок), `capacity` (число), `hasProjector` (логічне), `createdAt` (readOnly, призначає сервер).
   * Зв'язки: "Має багато `bookings`".
2. **`bookings`** (Бронювання)
   * Атрибути: `id` (readOnly), `roomId` (число), `userId` (число), `startTime` (дата і час), `endTime` (дата і час), `status` (рядок: `pending`, `confirmed`, `cancelled`), `createdAt` (readOnly).
   * Зв'язки: "Належить до `rooms`", "Належить до `users`".
3. **`users`** (Користувачі)
   * Атрибути: `id` (readOnly), `email` (рядок), `role` (рядок: `student`, `teacher`, `dispatcher`).

## 2. Таблиця маршрутів

| Операція | Метод і шлях | Успіх | Помилки (з обґрунтуванням) |
| :--- | :--- | :--- | :--- |
| Список аудиторій | `GET /rooms` | 200 | 400 (некоректні параметри пагінації/фільтрації), 401 (немає токена) |
| Створення аудиторії | `POST /rooms` | 201 + Location | 400 (зламаний JSON), 401 (не авторизовано), 403 (тільки для адмінів), 415 (не JSON), 422 (помилка валідації полів) |
| Читання аудиторії | `GET /rooms/{roomId}` | 200 | 401 (не авторизовано), 404 (аудиторію не знайдено) |
| Бронювання певної аудиторії | `GET /rooms/{roomId}/bookings` | 200 | 400 (помилка в параметрах), 401 (не авторизовано), 404 (аудиторію не знайдено) |
| Список усіх бронювань | `GET /bookings` | 200 | 400 (помилка в параметрах), 401 (не авторизовано) |
| Створення бронювання | `POST /bookings` | 201 + Location | 400 (зламаний JSON), 401 (немає токена), 415 (не JSON), 422 (дата в минулому або перетин часу) |
| Читання бронювання | `GET /bookings/{bookingId}` | 200 | 401 (не авторизовано), 404 (не знайдено) |
| Оновлення бронювання | `PATCH /bookings/{bookingId}` | 200 | 400 (зламаний JSON), 401 (не авторизовано), 403 (недостатньо прав), 404 (не знайдено), 422 (некоректні дані) |
| Видалення бронювання | `DELETE /bookings/{bookingId}` | 204 | 401 (не авторизовано), 403 (тільки диспетчер), 404 (не знайдено) |
| Підтвердження бронювання | `POST /bookings/{bookingId}/confirm` | 200 | 401 (не авторизовано), 403 (тільки диспетчер може підтверджувати), 404 (не знайдено), 409 (уже підтверджено або скасовано) |
| Скасування бронювання | `POST /bookings/{bookingId}/cancel` | 200 | 401 (не авторизовано), 403 (тільки диспетчер або автор), 404 (не знайдено), 409 (уже скасовано) |
| Список користувачів | `GET /users` | 200 | 401 (не авторизовано), 403 (тільки диспетчер) |

## 3. Фільтрація, сортування, пагінація
* **Колекція `rooms`**: 
  * Фільтрація: `capacity` (від певного числа), `hasProjector` (true/false).
  * Сортування: `name`, `-capacity` (за спаданням місткості).
  * Пагінація: розмір сторінки за замовчуванням 20, максимальний 100.
* **Колекція `bookings`**:
  * Фільтрація: `roomId`, `userId`, `status` (`pending`, `confirmed`).
  * Сортування: `startTime`, `-createdAt` (нові спочатку).
  * Пагінація: розмір сторінки за замовчуванням 20, максимальний 100.

## 4. Проєктні рішення
* **Ідемпотентність**: Методи `GET`, `PUT`, `DELETE` є ідемпотентними. Якщо клієнт надішле `POST /bookings` двічі через збій мережі, може створитися дублікат бронювання.
* **Версіонування**: Всі маршрути починатимуться з префікса `/api/v1`. Несумісними змінами (для v2) будуть: видалення поля, зміна типу даних поля, зміна структури відповіді.
* **Помилки**: Сервер повертатиме інформацію про помилки у стандартному форматі Problem Details (`application/problem+json`).
* **Адреса ресурсу**: Під час успішного створення (201 Created) клієнт отримуватиме адресу нового ресурсу в заголовку `Location`.
